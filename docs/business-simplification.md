# 面向小区助老业务的最小改造

## 业务边界

目标社区为 2500 名老人、250 名志愿者、25 名管理员。部署边界是单个后端 JVM、单个 MySQL 数据库。注册人数不是并发数，不据此推导系统已经能承载 2775 个同时操作的用户。

保留模拟支付，不宣称已接入真实支付、银行退款或资金对账。前端金额看板改为“模拟净收款”。

## 组件取舍

| 组件 | 真实职责 | 删除或停止的用途 |
| --- | --- | --- |
| MySQL、事务、条件更新 | 订单归属、预约状态、积分、审批、默认地址的最终一致性约束 | 不另外引入分布式 ID 服务 |
| Redis | 服务目录缓存、后台聚合缓存、账号及辅助 IP 限流 | 建单锁、接单锁、自动确认锁、管理员资料缓存、一天内登录计数 |
| RabbitMQ | 跨角色订单提醒、审批提醒及管理员群发，削峰并允许失败后重投 | 新订单和新接单不再生产固定 30 分钟 TTL 消息；正常启动不注册纯日志审计消费者 |
| Outbox | 业务事务与待发送通知一起提交，确认成功后标记已发送 | 不在业务事务中等待 Broker 确认 |
| WebSocket | 已持久化消息的在线提醒 | 不把在线连接当作通知的唯一存储 |
| BCrypt | 密码校验，保留强度 12 | 移除全部放行的 Spring Security 过滤器链，保留 JWT 角色拦截器 |
| 定时任务 | 依据预约时间复核超时，数据库中存在待补偿记录时可恢复处理 | 单 JVM 不再使用 Redis 调度锁 |
| Arthas | 本机手动诊断线程、调用耗时、JVM 状态 | 不自动附加、不开放公网、不在正式测量中进行方法增强 |
| Druid、MyBatis-Plus | 复用数据库连接、映射既有实体与分页，维持订单事务 | 不引入额外 ORM 或并行数据源 |
| JWT、拦截器 | 三种角色的请求身份与权限检查，结合实时账号状态 | 不以 JWT 验签代替账号停用校验 |
| OSS | 原有头像上传与删除的对象存储职责 | 本轮用测试替身，不对真实对象存储压测 |
| AOP、Swagger | 共用限流/缓存切面，开发接口联调与文档 | 不将接口文档和业务日志当作可靠审计或业务异步任务 |

群发使用现有 Outbox 和可靠消费容器；删除自调用 `@Async` 及独立群发线程池。每个收件人独立落库，失败重投保留事件 ID，数据库唯一键防止重复通知和已读状态被重置。

Redis 普通缓存和 Lua 限流复用 Lettuce 连接。项目没有额外引入连接池依赖，已移除不生效的 Redis 连接池映射配置。

## 主键与幂等

1. `order.id` 明确配置 `IdType.AUTO`，沿用数据库 `INT AUTO_INCREMENT`；Java 使用 `Long` 接收。单小区规模不需要雪花号或发号中心。
2. `order_no` 使用时间戳和完整 UUID，增加唯一约束，仅作业务展示和查询标识，不作主键。
3. 新增 `request_id`，使用大小写敏感的 ASCII 字符集，唯一键为 `(user_id, request_id)`。历史记录保留 NULL，不覆盖历史订单。
4. 创建订单先锁老人账号，再检查该账号的提交标识；并发重试返回同一订单，数据库唯一约束作最终保障。
5. 前端相同预约内容的重试复用标识；修改内容后换标识。购物车使用 `Idempotency-Key` 请求头，结算重试先返回旧订单，不清理后来加入的服务。
6. 不接收客户端指定的订单、服务项主键、金额、状态和归属。价格取当前上架套餐，积分不接受个人资料接口写入。

购物车读写和结算共用账号锁，使用读已提交隔离级别，避免首次提交时空幂等索引的间隙锁竞争。

## 已验证的修复

- 地址修改、删除、设默认同时检查账号归属；默认地址变更在事务内按账号串行化。
- 消息已读按消息 ID、接收者角色、接收者 ID 一起限定；管理员不再使用硬编码 ID 0。
- 头像只更新头像字段；删除头像显式写 NULL，避免覆盖并发积分。
- 停用或删除账号后，后续 HTTP 请求与新建 WebSocket 连接校验数据库实时状态，不只验证 JWT 签名。
- 停用志愿者沿用订单取消事务，同时处理父订单聚合、服务项、模拟退款和通知。脱敏手机号按主键区分，防止第二次删除撞唯一键。
- 接单锁顺序为志愿者账号、父订单、服务项。活动项查询不提前持有服务项锁，已经捕获并修复一次真实死锁，并做 20 次重复竞争回归。
- 去掉接单、完成时同步通知与 MQ 通知的重复；父订单聚合状态未变化时，仍能产生服务项动作提醒。
- 套餐新增、修改类型、下架、删除后失效相关目录缓存；存在外层事务时在提交后失效。
- 评分限制为 1 至 5 星；看板使用模拟支付减模拟退款，不将未支付订单金额计入收入。
- 中间件总开关约束业务缓存、限流、生产投递和消费监听。关闭 MQ 时保留 Outbox 待发送事件，恢复后继续投递。

## 旧消息迁移

停止生产旧 TTL 消息，不删除旧业务队列。保留历史超时消费者与 Outbox 类型白名单，允许旧记录安全消化。

本机旧审计队列已确认消息数和未确认数都为 0，才移除订单广播到日志专用队列的绑定；队列未删除、消息未清空。其他部署若仍有旧审计消息，应先启用 `middleware.rabbitmq.legacy-audit.enabled=true` 完成消化，再关闭并解除旧绑定。

增量脚本：先执行 `docs/migrations/20261004_fix_2_10.sql`，再执行 `docs/migrations/20261004_business_simplification.sql`。两份迁移都已在隔离库验证重复执行；主键及幂等迁移也已应用本机开发库。遇到重复历史订单号时唯一索引创建会失败，不能自动删除业务订单。

本地密钥配置未改动。开发配置文件摘要与改造前一致。

## 验证与压测

默认测试不连接开发库。历史演示测试需要明确设置 `takeme.legacy.demo.tests=true` 才执行；自动回归用随机 MySQL 测试库、随机 RabbitMQ 虚拟主机，并只清理自己创建的隔离资源。

工具、压测计划及运行方法见 `tools/README.md`。最终数据以 JMeter 原始 JTL、HTML 报告、数据库一致性检查和 JVM/队列快照为依据；不以接口 HTTP 200 代替业务成功，不把配置值称作已经实现的性能收益。

## 面试表述边界

- 可表述“单库行锁、状态条件更新、数据库幂等约束”，不能表述已经解决跨数据库或多地域一致性。
- 可表述“Outbox 与至少一次投递、消费去重”，不能表述 Exactly Once。WebSocket 临时提醒可能因重投再次出现，最终消息表不会重复。
- 可表述“有效推送连接的单 JVM 在线统计”，不能表述多节点、多端在线状态系统。
- JWT 为无状态凭据；退出由前端删除凭据和断开连接，不宣称实现全局 JWT 撤销列表。
- 超时扫描存在调度延迟，正常为下一轮扫描处理，不宣称预约时间到达的同一毫秒就回收订单。
- 历史缺少退款流水的数据不能凭订单状态反推资金明细，不能将模拟看板用于真实资金对账。
- 自动化回归和压测不能证明绝对没有其他缺陷；真实上线前仍需 TLS、备份恢复、独立服务账号、监控告警及人工业务验收。
